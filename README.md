# OCS 题库 AI 答题本地转发

一个极小的本地 HTTP 服务，把 OCS（Online Course Script）题库的答题请求转发给
任意 OpenAI 兼容的 AI 接口，并把模型返回的答案转换成 OCS 能直接选中的格式。

适用场景：给 OCS 的自定义题库接上 AI 自动答题。服务跑在本机
`http://127.0.0.1:8765`，不依赖任何公网中转，密钥只保存在你自己的 `.env` 里。

## 这个仓库里有什么

| 文件 | 说明 |
| --- | --- |
| `src/` | 服务源码（仅 Node.js 内置模块，零依赖） |
| `test/` | 单元测试，用 `node --test` 直接跑 |
| `ocs-answerer-config.js` | 可直接复制进 OCS 的题库配置 |
| `.env.example` | 配置模板，**不含任何密钥和模型名** |
| `start.cmd` | Windows 双击启动 |
| `AGENT_SETUP_PROMPT.md` | 让另一个 AI 智能体自动完成部署的提示词 |

## OCS 题库配置

把下面这段填进 OCS 的自定义题库设置（设置 → 题库 → 自定义题库 → 新增）：

```json
[
  {
    "name": "OCS AI 本地转发",
    "url": "http://127.0.0.1:8765/answer",
    "method": "post",
    "contentType": "json",
    "type": "fetch",
    "headers": {
      "Content-Type": "application/json"
    },
    "data": {
      "title": "${title}",
      "type": "${type}",
      "options": "${options}",
      "images": { "handler": "return (env)=> env.images || []" }
    },
    "handler": "return (res) => res.code === 1 ? [res.question, res.answer] : undefined"
  }
]
```

`ocs-answerer-config.js` 里是同一份内容，可以直接复制。

因为请求指向本地，脚本管理器会拦截。需要二选一：

- 在脚本头部加 `// @connect 127.0.0.1`，或
- 在脚本管理器的连接白名单里放行 `127.0.0.1`

## 方式一：手动部署（从零到能用，全步骤）

跟着做大约 10 分钟。以 Windows 为主，macOS / Linux 差异会单独标注。

### 1. 系统要求

- Windows 10/11、macOS 或任意主流 Linux；
- Node.js **18 或更高**（本服务零第三方依赖，装好 Node 就够了，不需要 `npm install`）；
- 一个 OpenAI 兼容的 AI 接口：接口地址 + API 密钥 + 至少一个支持 Chat Completions 的模型名；
- 如果你想让带图片的题目也能答，还需要一个**支持图片输入的多模态模型**。

### 2. 安装 Node.js

1. 打开 https://nodejs.org/ 下载 **LTS 版本**安装包（Windows 选 `.msi`）。
2. 一路下一步安装。安装完成后**新开一个终端窗口**（按 `Win + R`，输入 `cmd` 回车），
   运行：

   ```bash
   node --version
   ```

   显示 `v18` 及以上（例如 `v22.22.2`）即成功。
3. 如果提示「不是内部或外部命令」，说明终端还是旧窗口，重开一个；
   还不行就重启电脑再试。

### 3. 下载本仓库

二选一：

**A. 用 Git（推荐，以后更新方便）**

```bash
git clone https://github.com/xia3179679755-ui/ocs-ai-forwarder.git
cd ocs-ai-forwarder
```

没装 Git 就去 https://git-scm.com/downloads 装一个。

**B. 直接下载 ZIP**

打开仓库页面 → 绿色 `Code` 按钮 → `Download ZIP` → 解压到任意目录
（**路径里最好不要有中文和空格**，例如 `D:\ocs-ai-forwarder`），
终端里 `cd` 进这个目录。

### 4. 创建并填写 `.env`

`.env` 是唯一的配置文件，里面放你的密钥和模型，**永远不会进仓库**。

**Windows**：直接双击 `start.cmd`，它会自动复制 `.env.example` 为 `.env`
并用记事本打开；或者手动复制 `.env.example` 改名为 `.env`。

**macOS / Linux**：

```bash
cp .env.example .env
```

然后用任意编辑器打开 `.env`，至少填好这几项：

```ini
MOLLY_API_KEY=你的密钥
MOLLY_BASE_URL=https://你的接口地址/v1
MOLLY_CHAIN=<强模型>:max:90000,<备用模型>:medium:30000
MOLLY_CHAIN_IMAGES=<支持图片的模型>:medium:60000
```

注意：

- `MOLLY_BASE_URL` 通常以 `/v1` 结尾（以你的服务商文档为准）。
- 模型名填你在该服务商「模型广场 / 模型列表」里看到的**确切名字**。
  **本仓库不预设任何模型，也不会帮你猜。** 不知道有哪些模型可填时，
  可以让浏览器或 curl 访问 `GET 你的接口地址/models`（带上密钥）查看列表：

  ```bash
  curl -H "Authorization: Bearer 你的密钥" https://你的接口地址/v1/models
  ```

- `MOLLY_CHAIN` 的格式是 `模型名:思考强度:超时毫秒`，逗号分隔可写多档：
  - 第一档先跑，用满它自己的超时（例 90 秒）；
  - 第一档**超时、报错、或答案不在选项里**，自动切第二档（备用模型）；
  - 第二档拿到**完整的预算**，不是第一档剩下的时间。
- 只想要一个模型，就只写一段：`MOLLY_CHAIN=<强模型>:max:90000`。
- 不答图片题可以把 `MOLLY_CHAIN_IMAGES` 留空，会自动复用主链。

其余项保持默认即可（各项含义见下文「配置说明」）。保存并关闭文件。

### 5. 启动服务

**Windows**：双击项目目录里的 `start.cmd`，出现黑窗口并打印
`server_started` 即启动成功。

**macOS / Linux / 任意终端**：

```bash
node src/run.mjs
```

**保持这个窗口开着**--关掉窗口就等于停掉服务，答题期间不能关。

> 也可以先跑一遍测试确认代码没问题：`node --test test/*.test.mjs`。

### 6. 验证服务是否正常

**新开一个终端窗口**（原来的窗口被服务占着），依次执行：

```bash
curl http://127.0.0.1:8765/health
```

应返回 `{"ok":true,"service":"ocs-ai-forwarder"}`。

> 本机设置了 HTTP 代理的话，curl 请加 `--noproxy "*"`，否则会被代理拦下返回 502。

再发一道单选题做端到端验证：

```bash
curl -X POST http://127.0.0.1:8765/answer --noproxy "*" -H "Content-Type: application/json" -d "{\"title\":\"1+1等于几？\",\"type\":\"single\",\"options\":\"A. 1\\nB. 2\\nC. 3\"}"
```

应返回 `{"code":1,...,"answer":"B"}`。如果返回 `code:0`，去看
`logs\当天日期.log` 里 `[失败]` `[解析]` 那几行，通常是密钥、
地址或模型名填错了。

### 7. 配置 OCS

1. 打开 OCS 设置 → 题库 → 自定义题库，把本文开头「OCS 题库配置」那段 JSON
   （或 `ocs-answerer-config.js` 的内容）粘贴进去，保存并启用。
2. 放行本地连接，二选一：
   - 在 OCS 脚本头部加一行 `// @connect 127.0.0.1`；或
   - 在脚本管理器（Tampermonkey 等）的「跨域请求 / 连接白名单」里放行 `127.0.0.1`。
3. 进学习通等课程的答题页面，OCS 查题时会走本地 AI。第一次请求浏览器可能
   弹出「允许访问 127.0.0.1」的确认，点允许。

### 8. 创建桌面快捷方式（日常使用）

- 在文件管理器里右键 `start.cmd` → 发送到 → 桌面快捷方式；或
- 手动新建快捷方式，目标填 `start.cmd` 的**绝对路径**，
  「起始位置」填项目目录--**起始位置必须填**，否则读不到 `.env`。

以后双击桌面图标启动即可。**窗口开着服务就在跑，关窗口就是停服务。**

### 9. 卸载 / 更新

- 卸载：删除项目文件夹和桌面快捷方式即可，`.env` 里的密钥随文件夹一起删除。
- 更新：`git pull` 后重开 `start.cmd`（ZIP 下载的就重新下载解压覆盖）。

## 方式二：让 AI 智能体替你部署

不想自己动手？把部署这件事整个交给一个会操作电脑的 AI。

1. 打开仓库里的 [`AGENT_SETUP_PROMPT.md`](AGENT_SETUP_PROMPT.md)。
2. **复制其中代码框里的完整提示词**，并把提示词开头的
   `{仓库地址}` 替换成本仓库的 URL：
   `https://github.com/xia3179679755-ui/ocs-ai-forwarder.git`
3. AI 会自动完成：clone 代码 → 检查 Node.js → **向你询问** API 地址、密钥和
   模型名 → 写 `.env` → 启动服务 → 用 curl 验证判断题/单选题/多选题 →
   创建桌面快捷方式 → 输出 OCS 该填的题库配置。
4. 你只需要按它的提问提供密钥和模型名，最后把 AI 给出的题库 JSON 填进 OCS。

> 安全提示：AI 过程中只会在你本机操作；密钥写进的是 `.env`（已被 .gitignore
> 排除），不会进 git。如果你不放心，可以盯着它执行，提示词里已明确禁止它
> 修改服务监听地址、伪造模型名和提交 `.env`。

## 配置说明

所有配置都在 `.env` 里：

| 变量 | 说明 |
| --- | --- |
| `MOLLY_API_KEY` | 上游接口密钥。**不会进仓库，也不会写进日志** |
| `MOLLY_BASE_URL` | 上游地址，通常是 `https://xxx/v1` |
| `MOLLY_CHAT_PATH` | 请求路径，默认 `/chat/completions` |
| `MOLLY_CHAIN` | 答题阶梯链，见下 |
| `MOLLY_CHAIN_IMAGES` | 图片题专用链，留空复用主链 |
| `MOLLY_PROBE` | 难度探针，留空关闭 |
| `MOLLY_MAX_TOKENS` | 限制输出长度，默认 64 |
| `TOTAL_TIMEOUT_MS` | 单题总预算，默认 150 秒 |
| `MOLLY_CACHE_TTL_MS` | 答案缓存时长，默认 30 分钟，0 关闭 |
| `MOLLY_SERIALIZE` | 1=上游请求排队，OCS 关不掉并发时用 |
| `PORT` | 监听端口，默认 8765 |

### 答题阶梯链（含失败备用）

`MOLLY_CHAIN` 是唯一的调度来源。每档写成 `模型:思考强度:超时毫秒`，逗号分隔：

```ini
MOLLY_CHAIN=<强模型>:max:90000,<备用模型>:medium:30000
```

- 第一档先跑，用满 90 秒；
- 第一档**超时、报错、或答案不在选项里**，就自动切到第二档；
- 第二档是备用模型，拿到**完整的 30 秒预算**，不是第一档剩下的时间；
- 任何时刻只有一个请求在跑，一题不会花两份 token。

思考强度可以写 `low` / `medium` / `high` / `max`，或 `auto`（按难度探针的结果选）。
注意：**不传这个参数不等于自动**，多数上游会走它自己的默认档，往往比 `medium` 更慢。

### 图片题

新版 OCS 会把题目里的图片抽成 base64 单独传，题干里留下 `[图片1]`、`[图片2]`
这样的占位符。题库配置里要把图片传出来（本文开头的配置已包含）：

```json
"data": {
  "title": "${title}",
  "type": "${type}",
  "options": "${options}",
  "images": { "handler": "return (env)=> env.images || []" }
}
```

服务收到 `images` 后会按 OpenAI 兼容的多模态格式把图片随题发出去，
顺序与 `[图片N]` 的编号一一对应。答案里如果带 `[图片N]`，OCS 会自动还原成图片。

**注意两点：**

1. **不是每个模型都支持图片输入。** 实测下来差异很大：

   | 表现 | 说明 |
   | --- | --- |
   | 正常返回 | 接受 `image_url` 并作答 |
   | 直接断开连接 | 收到图片就 `fetch failed`，既不返回 200 也不返回 400 |

   所以图片题要走单独的链 `MOLLY_CHAIN_IMAGES`，别和主链混在一起--
   主链模型如果不支持图片，会白白等到超时。

2. **公式题目前无解。** OCS 没有公式相关的接口，公开文档和
   CHANGELOG 里都没有对应字段。

日志里会用 `[题目] 图片=N张` 标出，并在 `[原始]` 里只记图片数量和体积
（base64 直接进日志会刷屏）。

### 难度探针（默认关闭）

```ini
MOLLY_PROBE=<快模型>:minimal:12000
```

先让快模型判断这题该想多深，再让正式模型按这个深度作答。

**默认关闭**，因为它只在探针本身很快（1-3 秒）时才划算。实测在某些上游，
最低思考档的探针请求也要 28-56 秒，比直接答题还慢，纯属浪费。
只有当你确认上游响应很快时才打开它。

## 工作原理

```
OCS 发来一道题 → 查缓存 / 合并同题 → 调用上游模型 → 解析并对齐选项 → 返回答案
```

每一环的细节：

- **无状态**：每次请求只带当前这一题，没有对话历史，跑多久都不会变慢。
- **选项对齐**：选项自带字母（`A. 正确`）就返回字母；选项没字母（`对` / `错`）
  就返回**选项原文**。OCS 是按文字匹配的，返回错误的格式会选不中。
- **多选**：返回 `A#C` 形式；选项没字母时返回 `选项一#选项二`。
- **答案校验**：答案不在选项范围内就判失败，绝不伪造。
- **网络重试**：连接被上游中断（`fetch failed`）不等于没答出来，会立刻重发一次，
  且重发用的是该档剩余时间，不会把预算翻倍。
- **断开也继续算**：OCS 超时断开后，服务端仍会把答案算完并写入缓存，
  下次重试直接秒回。

## 协议端点

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/answer` | 答题主接口 |
| `OPTIONS` | `/answer` | 跨域预检，返回 204 |
| `HEAD` | 任意 | OCS 延迟探测，返回 200 空正文 |
| `GET` | `/health` | 健康检查 |

## 日志

终端的每一行都会同时写入 `logs\YYYY-MM-DD.log`，关掉窗口也不会丢。
Windows 下双击 `查看日志.cmd` 可用记事本打开当天的日志。

一次答题会打印：

1. `[本地]` 收到请求
2. `[原始]` OCS 发来的完整 JSON（排查格式问题用）
3. `[题目]` 题型、难度、将执行的链
4. `[请求]` 第几档、模型、思考强度、超时
5. `[失败]` 超时或上游错误
6. `[解析]` 原始返回、采用答案、是否匹配选项
7. `[返回]` 最终答案和总耗时

所有日志都会自动抹掉 `Bearer xxx` 和 `sk-xxx` 形态的密钥。

## 常见问题

**OCS 提示「没有匹配的选项」**
看日志的 `[解析]` 行。如果「可匹配=否」，说明模型给的答案不在题目选项里，
服务会拒绝返回（宁可不答也不乱选）。

**一直超时**
上游延迟本身波动很大，同一道题 3 秒到 70 秒都可能出现。把 `MOLLY_CHAIN`
第一档的超时调大（例如 90000），而不是切到别的模型。切模型不会让上游变快。

**同时答几道题会明显变慢**
实测同一道题单独请求 11.9 秒，两道题同时请求会拖到 65 秒超时。
在 OCS 里关掉并发，或设置 `MOLLY_SERIALIZE=1` 让上游请求排队。

**带图片的题答不了 / fetch failed**
主链模型大概率不支持图片输入。把 `MOLLY_CHAIN_IMAGES` 单独配成一个
确认支持多模态的模型。

**服务跑久了会不会变慢**
不会。每次请求独立无状态，输入 token 数量恒定。
